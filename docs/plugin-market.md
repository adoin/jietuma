# 插件市场

设置左侧的“插件”页包含“已安装”和“官方市场”。系统托盘或剪贴板设置菜单的“管理插件”直接定位此设置页；市场列表按 ID 标记已安装版本及停用状态，包括从本地包安装的插件。官方市场按需加载，支持本地搜索、下载安装；已安装页提供检查更新与单个更新。下载后仍需确认安装，检查更新不会自动安装。来源可以输入 GitHub 的 `owner/repo` 或 HTTPS 仓库链接添加，官方源不可移除，总数最多 16 个。

## 来源与更新

官方仓库名称和数字 ID 来自 `branding.json` 的 `plugins_repository`、`plugins_repository_id`。网络请求先按数字 ID 查询当前仓库名称，所以改名不会改变身份。自定义来源保存在本机设置 `plugins/market_sources`，不会随配置导入覆盖。

每个插件目录中的 `.market-source.json` 记录安装来源；该文件由宿主生成，安装包不能自行携带。与代码一起暂存并交换，更新保留 `.data/<id>.json` 配置和禁用状态。自定义来源安装的插件只向该来源检查更新；官方或本地安装的插件优先考虑自定义来源，同一来源只选可兼容平台/宿主的最新稳定版本，不降级。自定义源检查失败时暂停向官方回退，避免失败导致静默换源。

切换来源会在安装确认中明确显示；同版本换源或修复架构需要重新确认。同来源、兼容且同版本的包不会重复安装。手动本地安装更新成功后解除市场来源绑定；跳过的同版本包保留绑定。来源在用户确认后发生变化会拒绝安装，需重新确认。

## 协议与完整性

仅接受 schema 2 的完整 `plugin-market.json` Release 附件，字段包括 `repository_id`、40 位提交 `revision` 和 `plugins`。每个条目携带 `id`、SemVer `version`、`host`、`platform`、`release_tag`、`asset`、`asset_id`、`download_url`、`sha256`、`size` 以及名称和描述。顶层 `icons` 按插件 ID 保存 PNG 的 Base64。插件包命名为 `<id>-<version>-<platform>.jtbplugin`，Release 标签为 `<id>/v<version>`。

平台为 `windows-x86_64` 或 `windows-arm64`。宿主要求使用逗号相交的 `>=`、`>`、`<=`、`<`、`=` 三段 SemVer；预发布参与正常 SemVer 比较，但稳定市场不展示预发布包。目录保留历史版本，较新包要求更高宿主时可选择较旧兼容版本。

客户端按 Release 发布时间选择最新正式市场。下载前重新按仓库数字 ID 解析名称、查询对应 Release 及资产 ID；不直接访问目录指定的任意链接。校验资产名称、大小、可用的 GitHub 摘要、包 SHA-256，以及包内 ID、版本、平台、宿主范围和可执行文件架构。单包限 64 MiB，目录限 4 MiB / 4096 条目。原 ZIP 路径、解压大小和协议检查继续生效。

缓存位于插件目录 `.market-cache`，市场缓存 15 分钟；刷新绕过缓存，包按内容摘要缓存。安装的本地文件夹记忆不受市场缓存影响。存在 gh 时使用 gh 的认证；gh 失败不会匿名重试。未安装 gh 的 Windows 使用 WinHTTP 读取公共源，受 GitHub 公共 API 限流约束。HTTPS 与系统证书校验有效，二进制重定向仅允许 GitHub 的发布域名。

完整性校验不是作者签名或权限隔离。插件拥有当前用户的本机权限；用户仍需信任来源。

## 发布

插件仓库 [jietuma-plugins](https://github.com/adoin/jietuma-plugins) 独立维护插件版本，使用标签触发。每个版本双架构构建一次，已有版本复用不可变 Release；全部成功后才发布完整市场快照。普通提交不触发发布。详情见插件仓库 README。
